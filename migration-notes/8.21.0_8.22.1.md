# 8.21.0 → 8.22.1

The branch operations gained an `expand` parameter, and the floor plan moved.

**This release breaks java code.** See [Required migration](#required-migration).

## What changed
Two separate changes:

* every `BranchesApi` operation now takes a trailing `List<ExpandFields>` parameter —
  `branchesCreate`, `branchesRead`, `branchesUpdate` and their `WithHttpInfo` variants.
  No overload with the old parameter list was kept.
* `BranchData.floorPlan` was removed, together with its accessors. The floor plan image
  is now reached through the `floorPlanImage` expand field.

## Required migration

Add the argument. `null` means "expand nothing", which is what the previous behaviour
was:

```java
// before
BranchData branch = branchesApi.branchesRead(branchId);

// after
BranchData branch = branchesApi.branchesRead(branchId, null);
```

To read the floor plan, expand it instead of using the removed property:

```java
BranchData branch = branchesApi.branchesRead(branchId, Arrays.asList(ExpandFields.FLOORPLANIMAGE));
```
