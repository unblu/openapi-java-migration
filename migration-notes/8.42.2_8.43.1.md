# 8.42.2 → 8.43.1

The webhook registration model was renamed, and its operations gained an `expand` parameter.

**This release breaks java code.** See [Required migration](#required-migration).

## What changed

A webhook registration can now trigger an Aria agentic flow, carried in a new expandable
field `agenticFlowData`. Two things came with it, both in `WebhookRegistrationsApi`:

* **The model was renamed**, and the old names removed:

  | 8.42.2 | 8.43.1 |
  |---|---|
  | `WebhookRegistration` | `WebhookRegistrationData` |
  | `WebhookRegistrationList` | `WebhookRegistrationDataList` |
  | `WebhookRegistrationResult` | `WebhookRegistrationDataResult` |

* **Four operations gained a trailing `List<ExpandFields> expand` parameter**:
  `webhookRegistrationsCreate`, `webhookRegistrationsRead`,
  `webhookRegistrationsGetByName` and `webhookRegistrationsUpdate`, together with their
  `…WithHttpInfo` variants.

`webhookRegistrationsReadMultiple` and `webhookRegistrationsSearch` kept their parameters
but return the renamed list and result types. Delete, ping and reset-backoff are unchanged.

The rename also reaches two webhook event models: `WebhookPingEvent.webhookConfiguration`
and `WebhookExpiredEvent.webhookRegistration` are now typed `WebhookRegistrationData`. That
affects only code that receives webhooks and reads those fields.

29 findings in all, 9 in `models-v4` and 20 in `jersey3-client-v4`, from this one change.

**The wire did not break.** The JSON properties and the paths under
`/rest/v4/webhookregistrations/*` are unchanged. The renamed name does appear in `$_type`,
but on a model like this one `$_type` is informational: the server ignores it in a request,
and an `8.42.2` client reads `"$_type":"WebhookRegistrationData"` without error, its
`$_type` enum falling back to its single constant for any value.

## Required migration

Replace the three type names, and pass `null` as `expand` on the four operations that
gained it.

```java
// before
WebhookRegistration registration = new WebhookRegistration();
registration.setName("example-webhook");
WebhookRegistration created = webhookRegistrationsApi.webhookRegistrationsCreate(registration);
WebhookRegistration read = webhookRegistrationsApi.webhookRegistrationsRead(created.getId());
WebhookRegistration byName = webhookRegistrationsApi.webhookRegistrationsGetByName("example-webhook");
WebhookRegistration updated = webhookRegistrationsApi.webhookRegistrationsUpdate(read);
WebhookRegistrationList list = webhookRegistrationsApi.webhookRegistrationsReadMultiple(ids);
WebhookRegistrationResult result = webhookRegistrationsApi.webhookRegistrationsSearch(query);

// after
WebhookRegistrationData registration = new WebhookRegistrationData();
registration.setName("example-webhook");
WebhookRegistrationData created = webhookRegistrationsApi.webhookRegistrationsCreate(registration, null);
WebhookRegistrationData read = webhookRegistrationsApi.webhookRegistrationsRead(created.getId(), null);
WebhookRegistrationData byName = webhookRegistrationsApi.webhookRegistrationsGetByName("example-webhook", null);
WebhookRegistrationData updated = webhookRegistrationsApi.webhookRegistrationsUpdate(read, null);
WebhookRegistrationDataList list = webhookRegistrationsApi.webhookRegistrationsReadMultiple(ids);
WebhookRegistrationDataResult result = webhookRegistrationsApi.webhookRegistrationsSearch(query);
```

The imports change with them:

```java
import com.unblu.webapi.model.v4.WebhookRegistrationData;
import com.unblu.webapi.model.v4.WebhookRegistrationDataList;
import com.unblu.webapi.model.v4.WebhookRegistrationDataResult;
```

**`null` keeps the previous behaviour.** Without `expand`, `agenticFlowData` is neither
returned nor written: an update that does not name it leaves whatever flow is configured
on the registration untouched. Pass `List.of(ExpandFields.AGENTICFLOWDATA)` only when the
code actually reads or sets the flow.

A webhook receiver that reads `WebhookPingEvent.getWebhookConfiguration()` or
`WebhookExpiredEvent.getWebhookRegistration()` re-types the variable the same way.

## Also in this release, not breaking

* `AriaAgenticFlowDataContent` gained a `WEBHOOK` subtype, `AriaWebhookAgenticFlowDataContent`
  — the flow content a webhook registration carries. `EAriaAgenticFlowDataContentType`
  gained `WEBHOOK` and `EAriaAgenticFlowType` gained `WEBHOOK_MAIN` with it.
* `ExpandFields` gained `icon`.

All additive. An `8.42.2` client receiving one of the new enum values reads it as `null`,
as described in [8.41.4 → 8.42.2](8.41.4_8.42.2.md#also-in-this-release-not-breaking).
