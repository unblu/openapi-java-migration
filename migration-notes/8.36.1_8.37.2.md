# 8.36.1 → 8.37.2

Bot and suggestion source operations gained an `expand` parameter; the bot webhook payload classes were removed.

**This release breaks java code.** See [Required migration](#required-migration).

## What changed
Three separate changes:

* `BotsApi.botsCreate`, `botsRead`, `botsGetByName`, `botsUpdate` and
  `SuggestionSourcesApi.suggestionSourcesCreate`, `suggestionSourcesRead`,
  `suggestionSourcesGetByName`, `suggestionSourcesUpdate` — plus every `WithHttpInfo`
  variant — now take a trailing `List<ExpandFields>` parameter. No overload with the old
  parameter list was kept.
* the eight classes describing what a bot webhook receives were removed:
  `BotDialogOpenEvent`, `BotDialogClosedEvent`, `BotDialogMessageEvent`,
  `BotDialogMessageStateEvent`, `BotDialogCounterpartChanged`,
  `BotOnboardingOfferEvent`, `BotOffboardingOfferEvent`, `BotReboardingOfferEvent`.
* `AriaDialogBotData.agenticFlowId` and `AriaSuggestionSourceData.agenticFlowId` were
  removed, and `AnalyticsDataApi.analyticsDataInternal()` was removed.

At REST level the new `expand` query parameter is optional, so an un-migrated client
keeps working against a newer server — this is a java-only break.

## Required migration

Add the argument. `null` means "expand nothing", which is what the previous behaviour
was:

```java
// before
DialogBotData bot = botsApi.botsCreate(body);

// after
DialogBotData bot = botsApi.botsCreate(body, null);
```

Code that deserializes bot webhook payloads into the removed event classes has to be
reworked; there is no drop-in replacement type.
