# 8.2.0 → 8.3.1

Canned responses can no longer be searched on the `key` field.

**This release breaks java code.** See [Required migration](#required-migration).

## What changed
`KeyCannedResponseSearchFilter` and the enum constant
`ECannedResponseSearchFilterField.KEY` were removed.

The `CannedResponse` model never exposed a `key` property, so this filter could not
match anything a caller could read back.

## Required migration

Remove the filter. Canned responses can still be searched on `TITLE`, `TEXT`,
`OWNER_ID`, `OWNER_TYPE`, `CREATION_TIMESTAMP` and `MODIFICATION_TIMESTAMP`.

```java
// before
query.addSearchFiltersItem(new KeyCannedResponseSearchFilter()
        .field(ECannedResponseSearchFilterField.KEY)
        .operator(new EqualsStringOperator().value(key)));

// after — pick another field, for example the title
query.addSearchFiltersItem(new TitleCannedResponseSearchFilter()
        .field(ECannedResponseSearchFilterField.TITLE)
        .operator(new EqualsStringOperator().value(title)));
```

The server also stopped accepting `KEY`, so a client that is not migrated receives a
`400` rather than an empty result.
