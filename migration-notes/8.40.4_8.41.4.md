# 8.40.4 → 8.41.4

The label selection enum of the person visibility rules was renamed.

**This release breaks java code.** See [Required migration](#required-migration).

## What changed

`EPersonVisibilityLabelSelection` was renamed to `EVisibilityLabelSelection`, and the old
name was removed. This affects 22 method signatures across four model types:

* `PersonVisibilityRuleData` — `agentLabelSelection` and `visitorLabelSelection`
* `VisibilityRuleLabelSelectionOperator`
* `EqualsVisibilityRuleLabelSelectionOperator`
* `NotEqualsVisibilityRuleLabelSelectionOperator`

For each of them the getter, the setter and the fluent setter changed.

This is the same "drop the `Person` prefix from the label vocabulary" rename that turned
`PersonLabel` into `Label` in [8.39.3 → 8.40.4](8.39.3_8.40.4.md). The enum constants are
unchanged — `ALL`, `UNLABELED` and `DEFINED_LABELS` — so at REST level nothing changed and
the JSON is identical.

`PersonVisibilityRulesApi` itself was **not** renamed, and its
`/rest/v4/personvisibilityrules/*` paths still work.

## Required migration

Replace the type name. Nothing else has to change.

```java
// before
PersonVisibilityRuleData rule = new PersonVisibilityRuleData();
rule.setAgentLabelSelection(EPersonVisibilityLabelSelection.ALL);
rule.setVisitorLabelSelection(EPersonVisibilityLabelSelection.DEFINED_LABELS);

// after
PersonVisibilityRuleData rule = new PersonVisibilityRuleData();
rule.setAgentLabelSelection(EVisibilityLabelSelection.ALL);
rule.setVisitorLabelSelection(EVisibilityLabelSelection.DEFINED_LABELS);
```

The import changes with it:

```java
import com.unblu.webapi.model.v4.EVisibilityLabelSelection;
```

Variables and fields declared as the old type have to be re-typed the same way. Since the
constants keep their names, a plain type rename is the whole migration.

## Also in this release, not breaking

`ConversationHistorySearchFilter` gained a `LABELS` subtype,
`LabelsConversationHistorySearchFilter`, so conversation history can be searched by label.
Adding a subtype is additive: existing code keeps compiling and existing requests keep
working.
