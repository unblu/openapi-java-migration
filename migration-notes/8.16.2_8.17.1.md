# 8.16.2 → 8.17.1

The `autoOpen` flag of a branch client link was split in three.

**This release breaks java code.** See [Required migration](#required-migration).

## What changed
`BranchClientLinkData.autoOpen` was removed, together with its getter, setter and fluent
setter. It is replaced by three more specific properties:

* `autoOpenOnConnect`
* `autoOpenOnCallEnd`
* `autoOpenOnConversationEnd`

## Required migration

Pick the moment the link should open.

```java
// before
link.setAutoOpen(true);

// after — the closest equivalent
link.setAutoOpenOnConnect(true);
```

Worth doing promptly: a server still accepts a payload carrying the old `autoOpen`
property, but ignores it and returns it as `null`, so an un-migrated client loses the
setting without any error.
