# 8.41.4 → 8.42.2

Two polymorphic filter types gained a subtype.

**No java code has to change for this release.**

## What changed

`ConversationHistorySearchFilter` gained a `LAST_MESSAGE_SENT_OR_EDITED_TIMESTAMP` subtype,
`LastMessageSentOrEditedTimestampConversationHistorySearchFilter`, so a conversation history
search can filter on when a message was last sent *or edited* rather than only on when it
was sent.

`MessageExportFilter` gained a `SEND_OR_LAST_EDITED_TIMESTAMP` subtype,
`SendOrLastEditedTimestampMessageExportFilter` — the same distinction for the message
export.

Both are additive. The existing subtypes are untouched, no java signature changed, and
requests an `8.41.4` client already sends keep working.

## Also in this release, not breaking

Thirteen enums gained values, 38 constants in total. Nothing was removed from any of them,
and no type was removed.

* Nine are analytics enums gaining label-based grouping options — `ECallsCountGroupBy`,
  `EMessagesCountGroupBy`, `EQueueInteractionGroupBy` and six more.
* Two are the field enums that go with the new filter subtypes above,
  `EConversationHistorySearchFilterField` and `EMessageExportFilterField`.
* The remaining two are `EOnlineState`, which gained `OUT_OF_OFFICE`, and
  `EBranchClientIssueType`, which gained `MAIN_CAMERA_ACCESS_NOT_GRANTED`,
  `AUXILIARY_CAMERA_ACCESS_NOT_GRANTED` and `MICROPHONE_ACCESS_NOT_GRANTED`.

Adding a value to an enum requires no change to calling code. It is still worth knowing what
an `8.41.4` client does when an `8.42.2` server returns one of them: the generated enums are
closed, so the unknown value arrives as `null` rather than as a constant. That is
`READ_UNKNOWN_ENUM_VALUES_AS_NULL`, which the client has set for itself since `8.13.1` —
verified here by reading an `OUT_OF_OFFICE` person state with the `8.41.4` client's own
mapper. Code that reads one of these enums should handle `null`.
