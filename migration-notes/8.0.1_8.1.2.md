# 8.0.1 → 8.1.2

The `expand` parameter changed type on every operation that has one.

**This release breaks java code.** See [Required migration](#required-migration).

## What changed
Every operation that accepts an `expand` parameter now takes a `List<ExpandFields>`
instead of a comma separated `String`. This affects 190 method signatures across 13 API
classes: `AccountsApi`, `ApiKeysApi`, `AuthenticatorApi`, `ConversationHistoryApi`,
`ConversationsApi`, `ConversationTemplatesApi`, `CustomActionsApi`,
`ExternalMessengersApi`, `GlobalApi`, `NamedAreasApi`, `PersonsApi`, `TeamsApi` and
`UsersApi` — the plain and the `WithHttpInfo` variant of each.

No overload with the old parameter list was kept, so every call site has to be changed.

At REST level nothing changed: `expand` was and remains an optional query parameter.

## Required migration

Replace the comma separated string with the matching `ExpandFields` constants.

```java
// before
Team team = teamsApi.teamsCreate(body, "configuration,text");

// after
Team team = teamsApi.teamsCreate(body, Arrays.asList(ExpandFields.CONFIGURATION, ExpandFields.TEXT));
```

`null` keeps working and still means "expand nothing":

```java
teamsApi.teamsRead(teamId, null);   // unchanged
```

The constant for a value is the value upper-cased with any non-word character replaced
by `_` — `actionIcon` becomes `ACTIONICON`, `floorPlanImage` becomes `FLOORPLANIMAGE`.
If the value is only known at run time, `ExpandFields.fromValue(String)` does the
conversion, and throws on a value the client does not know.
