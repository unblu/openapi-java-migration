# 8.6.1 → 8.7.0

Persons can no longer be searched by label *name*.

**This release breaks java code.** See [Required migration](#required-migration).

## What changed
Three classes and two enum constants were removed:

* `PersonLabelNamePersonSearchFilter`
* `PersonLabelNamePersonTypedSearchFilter`
* `HavingPersonLabelNameOperator`
* `EPersonSearchFilterField.PERSON_LABEL_NAME`
* `EPersonTypedSearchFilterField.PERSON_LABEL_NAME`

Searching persons by the *identifier* of their labels is unaffected.

## Required migration

Move to the label-id filter, which remains available under the `PERSON_LABELS` field.

```java
// before — by label name
query.addSearchFiltersItem(new PersonLabelNamePersonSearchFilter()
        .field(EPersonSearchFilterField.PERSON_LABEL_NAME)
        .operator(new HavingPersonLabelNameOperator().addValuesItem("premium-support")));

// after — by label id
query.addSearchFiltersItem(new PersonLabelsPersonSearchFilter()
        .field(EPersonSearchFilterField.PERSON_LABELS)
        .operator(new AnyOfPersonLabelsOperator().addValuesItem(labelId)));
```

Resolve the name to an id first with `personLabelsGetByNames(..)`.

The server also stopped accepting `PERSON_LABEL_NAME`, so a client that is not migrated
receives a `400`.
